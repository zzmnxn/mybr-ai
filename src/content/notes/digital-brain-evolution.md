[첫 번째 글](../why-my-digital-brain)에서는 mybr.ai를 만들게 된 이유와 첫 배포까지의 과정을 정리했다. 사이트를 만들고 나서 기존 티스토리 글도 옮기고, 새롭게 공부한 내용도 조금씩 정리하고 있다. 처음에는 흩어져 있던 개발 기록을 한곳에 모으고 글 사이의 관계를 그래프로 보여주는 것만으로도 충분할 거라고 생각했다.

그런데 막상 사용하다 보니 조금씩 욕심이 생겼다. 글을 작성하면 그래프에 새로운 노드가 추가되고, 관련된 지식끼리 연결되는 건 좋은데 정작 내가 언제 어떤 공부를 했는지는 알기 어려웠다. 예전에 작성한 글을 다시 읽거나, 이해하지 못했던 내용을 보완하는 것도 공부인데 이런 활동은 어디에도 남지 않았다.

그러다가 GitHub 잔디를 보면서 문득 생각이 들었다. GitHub는 커밋을 하면 잔디가 채워지는데, 내가 공부한 기록도 이렇게 눈에 보이면 좀 더 동기부여가 되지 않을까? 나중에 돌아봤을 때 얼마나 꾸준히 공부했는지도 확인할 수 있고, 그동안 쌓인 기록을 보는 재미도 있을 것 같았다.



## GitHub 잔디를 내 방식대로 만들어 보기

그래서 활동 캘린더를 추가하기로 했다. 다만 GitHub처럼 날짜마다 네모난 칸을 만들고 활동량에 따라 색을 채우는 방식은 조금 아쉬웠다. mybr.ai 자체가 점과 선으로 지식을 표현하는 사이트인데, 캘린더도 그 디자인과 연결되면 좋겠다는 생각이 들었다.

처음에는 활동 종류마다 아이콘을 다르게 할까 생각했는데, 하루에 글도 쓰고 복습도 하고 여러 활동을 할 수 있으니 아이콘 하나로 대표하기가 애매했다. 그래서 활동 종류보다는 **그날 얼마나 많은 활동을 했는지**에 따라 아이콘이 변하도록 했다.

활동이 하나면 점 하나, 두 개면 선으로 연결된 두 점, 세 개부터는 작은 네트워크가 만들어지고 활동이 많아질수록 연결 구조가 복잡해지는 방식이다. 날짜도 일반적인 달력처럼 격자 형태로 배치하지 않고, 물결 모양의 선을 따라 이어지도록 디자인했다.

이렇게 하면 하루 동안 한 활동들이 하나의 작은 네트워크로 합쳐지고, 그 네트워크들이 날짜를 따라 연결되면서 한 달의 기록이 만들어진다. 현재 [Activity](../../activity)에서 날짜를 누르면 그날 발행한 글과 직접 남긴 수정·복습 기록을 확인하고 해당 글로 이동할 수 있다. 월을 이동하거나 지도와 목록 보기를 전환할 수 있고, 특정 날짜를 주소로 공유할 수도 있다.

물론 모든 활동을 자동으로 기록할 수 있는 건 아니다. 현재 자동으로 만드는 활동은 글의 `publishedAt`을 기준으로 한 발행 기록이다. 수정과 복습은 실제로 한 일을 확인해 별도 공개 활동 파일에 직접 남긴다. Git 커밋이나 파일 수정만으로 공부했다고 판단하지는 않는다.

글을 다시 열었다는 사실과 복습했다는 사실도 구분했다. 그래프에 남는 방문자의 탐색 경로는 브라우저 안의 기록이고, Activity에 보이는 것은 작성자가 공개한 활동이다. 단순히 글을 읽었다고 복습 횟수가 늘어나지 않는다. 캘린더의 점은 이렇게 확인 가능한 활동 수를 보여 주며, 학습 시간이나 이해도를 뜻하지는 않는다.

## 캘린더를 생각하다 보니 또 다른 기능이 떠올랐다

날짜를 점과 선으로 연결하는 UI를 구상하다 보니, 이걸 지식 자체에도 적용하면 좋겠다는 생각이 들었다.

지금 뇌 그래프에서는 어떤 글들이 연결되어 있는지는 볼 수 있지만, 그 지식을 얻기까지 어떤 과정을 거쳤는지는 글을 하나씩 읽어야 알 수 있다. 특히 트러블슈팅 글은 문제를 발견하고 원인을 분석하고 여러 방법을 시도한 뒤 해결하는 과정이 중요한데, 이런 흐름을 하나의 경로로 보여주면 어떨까 싶었다.

그래서 생각한 게 **Knowledge Paths**다. 예를 들어 `문제 발견 → 원인 분석 → 해결 시도 → 최종 해결 → 배운 점`처럼 실제 문제 해결 과정을 따라가며 관련 글을 읽을 수 있도록 하는 기능이다. 기존 Markdown 글을 단계별로 참조하고, 각 단계에 제목과 설명을 붙이는 방식으로 구현했다. 글 본문을 복제할 필요는 없지만, 어떤 순서로 읽으면 좋을지와 단계별 맥락은 따로 작성해야 한다.

현재 [Paths](../../paths)에는 C++ 컨테이너를 고르는 경로가 있다. vector에서 시작해 stack·queue, set, map을 차례로 읽는다. 트러블슈팅의 해결 과정을 따라가는 것은 활용 예시이고, 지금 공개된 경로는 관련 개념을 순서대로 읽는 형태다. 단계에 마우스를 올리면 그래프에서 관련 글이 강조된다.

여기서 한 가지 더 생각난 건 시간에 따른 그래프의 변화다. 지금 그래프는 현재까지 쌓인 지식을 보여주는데, 한 달 전이나 두 달 전의 그래프도 볼 수 있다면 재미있을 것 같았다. 처음에는 노드가 몇 개 없었지만 시간이 지나면서 새로운 지식이 추가되고 연결이 늘어나는 모습을 확인하는 것이다.

이 기능은 **Temporal Brain**이라고 이름 붙였고, 현재 화면에서는 [History](../../history)로 제공한다. 날짜를 고르면 그날까지 이 사이트에 발행된 글만 그래프에 남는다. 이전·다음 발행일로 이동하거나 오늘과 비교해 이후 추가된 글을 확인할 수 있다.

다만 이 화면은 과거 그래프의 완전한 복원은 아니다. 기준은 글의 생성일이나 원래 블로그의 작성일이 아니라, mybr.ai의 `publishedAt`이다. 당시의 연결 관계, 본문, 성장 단계는 복원하지 않으며 History 그래프에는 글 점만 표시한다. 점을 누르면 현재의 글로 이동한다. 과거의 상태를 모두 재현한다고 표현하기보다는, 공개한 지식이 시간에 따라 얼마나 늘었는지 보여 주는 기능에 가깝다.

## 기존 구조는 최대한 유지하기

기능이 늘어나다 보니 아키텍처도 다시 생각하게 됐다. 현재 mybr.ai는 Astro와 Markdown을 기반으로 하고, GitHub Pages로 배포하고 있다. 콘텐츠를 작성하고 Git에 반영하면 빌드 과정에서 글과 그래프 데이터가 생성되는 구조다.

이번에 추가한 기능들도 이 구조를 유지했다.

| 기능 | 데이터 관리 방식 |
|---|---|
| 기존 기술 글 | Markdown |
| 지식 그래프 | Markdown의 태그 및 관계 |
| Activity Calendar | 발행일 메타데이터 + 직접 확인해 남긴 공개 활동 |
| Knowledge Paths | 기존 글의 고유 ID를 단계별로 참조하는 경로 정의 |
| Temporal Brain / History | mybr.ai 발행일을 기준으로 선택한 날짜까지의 글 표시 |

별도의 서버나 DB 없이 빌드 과정에서 필요한 정적 페이지와 JSON 데이터를 생성하고, 브라우저에서 시각화한다. JavaScript가 꺼져 있어도 Activity의 월별 목록과 History의 발행일순 목록으로 글을 찾을 수 있다.

물론 나중에 웹에서 직접 복습 기록을 저장하거나 활동을 비공개로 관리하고 싶어진다면 DB와 인증이 필요할 수도 있다. 하지만 지금은 혼자 사용하는 사이트인 만큼 처음부터 모든 기능을 구현하기보다는 실제로 필요한 시점에 확장하는 게 나을 것 같다.

## 다시 찾기 위한 작은 기능들

글을 찾고 다시 읽는 기능도 보완했다. 글 제목 아래의 별을 누르면 사이드바의 즐겨찾기에 모인다. 즐겨찾기는 방문자의 브라우저에만 저장되며, 계정이나 기기 간 동기화는 없다. 그래프에서 지나간 길을 남기는 기능과도 별개다.

홈의 고정 글은 작성자가 직접 고른 글을 보여 주는 자리다. 방문자가 선택하는 즐겨찾기와 작성자가 공개하는 고정 글을 나누어, 개인적으로 다시 볼 글과 사이트에서 먼저 보여 줄 글을 구분했다.

## 앞으로

Activity, Paths, History는 각각 언제 무엇을 했는지, 어떤 순서로 읽으면 좋은지, 공개한 글이 시간에 따라 어떻게 늘었는지를 보여 준다. 같은 글을 서로 다른 관점에서 다시 찾을 수 있는 구조가 생겼다. 다만 경로를 만드는 일과 수정·복습을 기록하는 일은 여전히 직접 해야 한다. 화면이 있다고 기록이 저절로 쌓이는 것은 아니다.

추후에는 글에서 바로 복습 완료를 기록하거나, 복습할 글을 Todo와 연결하는 기능도 생각하고 있다. 다만 이것들은 실제로 사용하면서 필요성을 느낄 때 추가할 예정이다.

처음에는 글들을 한곳에 모아서 연결하는 게 목적이었는데, 만들다 보니 단순히 지식을 저장하는 것보다 **지식이 쌓이는 과정까지 기록하는 것**에 더 관심이 생긴 것 같다. 이제는 구현한 기능들을 실제로 사용하면서, 다시 읽고 정리하는 데 얼마나 도움이 되는지 확인해 보려고 한다.
